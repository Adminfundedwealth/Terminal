## ROOT CAUSE CANDIDATES

### 1. **Terminal: SSO_API_KEY Not Configured** ⚠️ HIGH PROBABILITY

**File:** `server/routes/auth.routes.js:138-145`

```javascript
const expectedKey = process.env.SSO_API_KEY || process.env.PROVISIONING_API_KEY;

if (!expectedKey) {
  return res.status(500).json({
    error: 'server_error',
    message: 'SSO API key not configured on server.',
  });
}
```

**Symptom:** Terminal returns HTTP 500  
**Fix:** Set `SSO_API_KEY` environment variable on Terminal production server  
**Verification:** Run `echo $SSO_API_KEY` on production server

---

### 2. **API Key Mismatch** ⚠️ HIGH PROBABILITY

**File:** `server/routes/auth.routes.js:147-152`

```javascript
if (!apiKey || apiKey !== expectedKey) {
  return res.status(403).json({
    error: 'forbidden',
    message: 'Invalid or missing x-sso-api-key header.',
  });
}
```

**Symptom:** Terminal returns HTTP 403 Forbidden  
**Fix:** Ensure Main Website and Terminal have the SAME `SSO_API_KEY`  
**Verification:**
- Check Main Website env: `SSO_API_KEY` or `TERMINAL_SSO_KEY`
- Check Terminal env: `SSO_API_KEY`
- Compare: They MUST match exactly

---

### 3. **Main Website: Missing x-sso-api-key Header** ⚠️ MEDIUM PROBABILITY

**Main Website Code** (NOT in this repo)

```javascript
// WRONG (missing header)
fetch('https://terminal.fundedwealth.com/auth/sso/generate', {
  method: 'POST',
  body: JSON.stringify({ fwUserId, accountId }),
});

// CORRECT
fetch('https://terminal.fundedwealth.com/auth/sso/generate', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-sso-api-key': process.env.TERMINAL_SSO_KEY, // ← REQUIRED
  },
  body: JSON.stringify({ fwUserId, accountId }),
});
```

**Symptom:** Terminal returns HTTP 403  
**Fix:** Add `x-sso-api-key` header in Main Website backend  
**Verification:** Check Main Website's Launch Terminal API handler

---

### 4. **Main Website: Missing fwUserId or accountId** ⚠️ MEDIUM PROBABILITY

**File:** `server/routes/auth.routes.js:156-162`

```javascript
if (!fwUserId || !accountId) {
  return res.status(400).json({
    error: 'validation_error',
    message: 'fwUserId and accountId are required.',
  });
}
```

**Symptom:** Terminal returns HTTP 400 Bad Request  
**Fix:** Ensure Main Website passes both fields:
- `fwUserId` — User's ID from Main Website database
- `accountId` — UUID from `trading_accounts.id` (created during provisioning)

**Verification:**
```sql
-- Check if trading account exists for this user
SELECT id, account_code, trader_id, status
FROM trading_accounts
WHERE trader_id = (
  SELECT id FROM terminal_traders WHERE external_id = '<fwUserId>'
)
AND status = 'active';
```

### 6. **Database Issue: trading_accounts Record Missing** ⚠️ MEDIUM PROBABILITY

**Context:** Even if SSO token is generated, the user will fail at Step 5 if:
- No `trading_accounts` record exists for the `accountId`
- Account status is NOT `active` (e.g., `suspended`, `breached`, `closed`)
- Account's `trader_id` doesn't match the user's `terminal_traders.id`

**File:** `server/services/sso.service.js:139-159`

```javascript
const { data, error } = await supabase
  .from('trading_accounts')
  .select('id, account_code, challenge_id, broker_provider, balance, status')
  .eq('id', accountId)
  .eq('trader_id', trader.id)
  .single();

if (error || !data) {
  return { success: false, error: 'Trading account not found or not assigned to this user.' };
}

if (data.status !== 'active') {
  return { success: false, error: `Trading account is ${data.status}. Cannot access terminal.` };
}
```

**Fix:** Verify provisioning completed successfully:
```sql
-- Check if account was provisioned correctly
SELECT 
  ta.id,
  ta.account_code,
  ta.trader_id,
  ta.status,
  tt.external_id AS fw_user_id,
  ca.status AS challenge_status
FROM trading_accounts ta
JOIN terminal_traders tt ON ta.trader_id = tt.id
LEFT JOIN challenge_accounts ca ON ta.challenge_id = ca.id
WHERE ta.id = '<accountId>';
```

## CONCLUSION

**The error originates from the Main Website backend, not the Terminal.**

The Terminal's `/auth/sso/generate` endpoint is correctly implemented and will return specific error codes:
- **500**: SSO_API_KEY not configured
- **403**: Invalid or missing API key
- **400**: Missing required fields

The Main Website backend catches these errors and displays "Failed to generate terminal session" to the user.

**Immediate Action Required:**
1. Run `node test-sso-generate.js` to test Terminal endpoint
2. Check Main Website logs for the actual HTTP error response
3. Verify `SSO_API_KEY` is set on Terminal production server
4. Verify Main Website has matching `SSO_API_KEY` and sends it in headers

**Once the exact error is identified from Main Website logs, apply the corresponding fix from the "ROOT CAUSE CANDIDATES" section above.**
